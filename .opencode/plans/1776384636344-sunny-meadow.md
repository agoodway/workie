# Codex `setup` / `cleanup` Plan

## Goal

Add two new commands, `workie setup` and `workie cleanup`, for Codex-managed worktrees.

- `setup` should do everything `begin` does after `git worktree add`
- `cleanup` should do everything `finish` does before `git worktree remove`
- Codex will provide paths via flags with environment fallback:
  - `--source-tree-path` or `CODEX_SOURCE_TREE_PATH`
  - `--worktree-path` or `CODEX_WORKTREE_PATH`
- Keep existing `begin` and `finish` behavior unchanged
- Do not add `--issue` support to `setup`
- Do not add branch pruning or worktree removal to `cleanup`

## Recommended Approach

1. Add `cmd/setup.go`.
   - Command shape: `workie setup [branch-name]`
   - Flags: `--source-tree-path`, `--worktree-path`
   - Resolve paths from flags first, then Codex env vars
   - Bootstrap `manager.WorktreeManager` the same way as other commands
   - Validate that the resolved source tree matches `wm.RepoPath`
   - Derive `branchName` from the positional arg or `filepath.Base(worktreePath)`
   - Reuse extracted manager logic to copy configured files and run `post_create` hooks against the existing worktree path

2. Add `cmd/cleanup.go`.
   - Command shape: `workie cleanup [branch-name]`
   - Flags: `--source-tree-path`, `--worktree-path`, `--force`
   - Resolve paths from flags first, then Codex env vars
   - Validate source tree, worktree path, and branch/path consistency the same way as `setup`
   - Reuse extracted cleanup-preflight logic to run `pre_remove` hooks and dirty-worktree checks
   - Do not call `git worktree remove`
   - Do not call branch deletion logic

3. Extract the post-create lifecycle from `manager.CreateWorktreeBranch`.
   - Add a helper in `manager/manager.go` such as `SetupExistingWorktree(branchName, worktreePath string) error`
   - Move these existing steps into that helper:
     - copy configured files
     - run `post_create` hooks
     - print success/path output
   - Keep `CreateWorktreeBranch` intact by having it create the worktree, then delegate to the new helper

4. Extract the pre-remove lifecycle from `cmd/finish.go`.
   - Add a helper such as `prepareWorktreeCleanup(wm, branchName, worktreePath string) error`
   - Move these existing steps into that helper:
     - branch name validation
     - worktree path existence check
     - `pre_remove` hooks
     - dirty-worktree check via `checkWorktreeStatus`
   - Keep `finishWorktree` intact by using the helper, then continuing with `git worktree remove` and optional branch pruning

5. Add a small Codex-specific path resolver helper under `cmd/`.
   - Keep Codex env handling out of the manager package
   - Shared responsibilities:
     - resolve flag vs env precedence
     - normalize paths with `filepath.Abs` / `filepath.Clean`
     - derive branch from worktree path when omitted
     - fail with clear messages when required path inputs are missing

## Validation Rules

- `source-tree-path` must resolve to the same repo root as `wm.DetectGitRepository()`
- `worktree-path` must exist and be a directory when `setup` or `cleanup` runs
- `worktree-path` should not equal the repo root
- If a branch name is provided, it must match `filepath.Base(worktreePath)`
- If no branch name is provided, derive it from `filepath.Base(worktreePath)`
- `cleanup` should preserve the current dirty-worktree safety check and only bypass it with `--force`
- Hook failures should preserve current behavior: warn, but do not abort the entire flow unless the shared hook executor already returns a hard failure case

## Files To Modify

- `cmd/setup.go`
- `cmd/cleanup.go`
- `cmd/root.go` (only if command help/examples need updates)
- `cmd/finish.go`
- `manager/manager.go`

## Verification

1. Run `go test ./...`
2. Regression check existing behavior:
   - `workie begin feature/test-branch`
   - `workie finish feature/test-branch`
3. Manual Codex-style setup flow:
   - create a worktree externally
   - run `workie setup --source-tree-path <repo> --worktree-path <worktree>`
   - confirm configured files are copied and `post_create` hooks run in the worktree
4. Manual Codex-style cleanup flow:
   - run `workie cleanup --source-tree-path <repo> --worktree-path <worktree>`
   - confirm `pre_remove` hooks run and no worktree removal occurs
   - add uncommitted changes and confirm cleanup blocks unless `--force` is used
5. Env fallback checks:
   - verify `CODEX_SOURCE_TREE_PATH` and `CODEX_WORKTREE_PATH` work without flags
   - verify explicit flags override env vars

## Notes

This plan intentionally keeps the change small:

- no changes to `begin` / `finish` UX
- no new global config behavior
- no issue-provider support for `setup`
- no branch pruning in `cleanup`
- Codex-specific behavior stays isolated to the new commands and small shared helpers
